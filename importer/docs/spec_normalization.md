# 正規化の設計判断

派生層 (制作年・作者の役割・名寄せ・日本語訳) について、コードを読んでも分からない
「なぜそうしたか」「なぜそうしなかったか」だけを書く。ルールそのものは各スクリプトを、
テーブルの分け方は `spec_schema.md` を見ること。

## 制作年 (`normalize_dates.rb`)

### BCE は素直な負数にした。天文学的年表記にはしなかった

当初は BCE 100 年 = `-99` (天文学的年表記) を考えたが、AIC (`-100`)・Cleveland
(`-1391`)・Paris Musées (`-4205`)・Rijksmuseum のテキスト (`-1700`) がそろって
「BCE n = `-n`」を使っていた。ここだけ流儀を変えると、館の構造化値をそのまま流用
できなくなる。

### 館の数値を主にし、テキストは precision の判定に回した

Smithsonian と Rijksmuseum 以外は館が開始年・終了年を数値で持っており、質も良い。
自由記述を自前でパースするより確実なので数値を採る。ただし数値には「頃」か
「ちょうど」かが残っていないので、precision はテキストか館の精度欄から決める。

### 数値とテキストが食い違うときは、個別にどちらを信じるか決めた

一律に「数値優先」にしなかったのは、館ごとに壊れ方が違うため。

- 単年テキストが数値の範囲外ならテキストを信じる。Cleveland には `"1970"` に
  earliest=1965 が付くような不整合が単年の約 1.9% ある
- `start > end` は終了年を捨てる。Paris Musées に、月日まで同じで年だけ 1 年前という
  明らかな入力ミスがある
- `decade` と `century` はテキストではなく数値の幅で決める。`"1700s"` は Smithsonian
  では 10 年、Cleveland では 18 世紀を指し、テキストからは区別できない

### 終了年の欠損を「以降 (after)」と読まなかった

Paris Musées は `endYear` の充足率が 15% 程度しかなく、大半は単に「その年の作品」を
意味している。欠損を開放区間と読むと、ほとんどの作品が「〜年以降」になってしまう。
同じ理由で、テキストが `before 1896` でも館が上下限を持っていれば範囲として扱う。

### `circa` に幅を持たせなかった

`ca. 1700` を 1695〜1705 のように広げる案はあったが、幅の決め方に根拠が無い。年は
そのまま入れ、不確かさは precision で表す。検索側で `circa` を除外することもできる。

### Smithsonian の `indexedStructured.date` は使わなかった

構造化値に見えるが、中身は検索ファセット用の年代バケットで、`"1615-1868"` (江戸時代)
や `"1914-1918"` (第一次世界大戦) のような時代区分タグが混ざっている。開始年・終了年
としては使えない。

## 作者の役割 (`normalize_artists.rb`)

### `creator` は既定値ではなく、語彙に載っているときだけ付けることにした

以前は判別できない役割を `creator` に倒していたため、「判定した結果 creator」と
「材料が無いので creator」が区別できなくなっていた。語彙に無い役割は `unknown`、
役割の情報自体が無いソースは NULL と分けてある。

## 作者の名寄せ (`normalize_person.rb`)

### 見逃しより誤統合を避けた

別人を 1 人に潰すと、その作者の作品一覧に他人の作品が混ざって気づきにくい。
見逃しは「同じ人が 2 人いる」だけで害が小さい。だから生没年がずれていれば統合しない。
ただしこれは「別人と確定」ではなく保留の意味で、Titian の生年のように同一人物でも
館の中で値が割れることは普通にある。

### 生没年は ±3 年を一致とみなした。完全一致にはしなかった

名前が完全一致するのに別クラスタになっていた組を調べると、生没年が ±3 年に収まる
標本 22 組がすべて同一人物だった。館ごとに 1〜3 年ぶれるのはこの分野では通常のカタログ
差異。既知の別人の例 (Hiller 父子、同姓同名の Campbell / Brown) は 26 年以上ずれるので、
この幅では触れない。

比較は代表値どうしではなく集合どうしにした。代表値 (最小値など) を選ぶと、館の中で
生年が 1791 と 1793 に割れている人物が他館の 1793 と食い違って却下されていた。

### 年が埋まっていても、根拠にしない年がある

生没年ゲートは年が実在の伝記情報であることが前提で、そうでない値が通ると
偽の確証を与える側に回る。

- Paris Musées の `(signataire)` 群は 500 人以上が全員 `1770/-`
- Met は活動期を `1800-1900` のような「ちょうど 100 年幅」で生没年欄に入れている。
  コホート検出 (同じ年組を 20 人以上が共有) は完全一致しか数えないので、±3 年を許すと
  `1802-1900` のような近傍がすり抜ける。そのため幅 100 年ちょうどは別に弾いている
- 段階 4 の自由記述パースは、`active` / `fl.` / `founded` を含む文字列を丸ごと捨てる。
  一部だけ救おうとすると活動期間や設立年を生没年として登録してしまう

### 括弧の扱いをソースごとに変えた

Cleveland や AIC の `(American, 1863–1937)` は国籍と生没年なので落としてよい。
一方 Rijksmuseum の `(II)` `(1612-1695)` `(schrijver)` は、館が同名の別人を区別する
ために付けた識別子で、落とすと Met の喜多川歌麿と Rijksmuseum の二代目歌麿が融合する。
Paris Musées の `(dessinateur)` `(l'Aîné)` も同様に残している。その代わり、括弧付きの
Paris の作者は他館の同一人物と名前で一致しなくなる (recall を捨てている)。

### コロン形式の役割は、役割語のホワイトリストでだけ剥がした

Met の `Watchmaker: Vaucher Fréres` のコロンの前を無条件に剥がすと、
`Le Caricaturiste :` (新聞名) や `Attributed to the Class N: …` のように名前そのものが
消える。ホワイトリストでも 1,325 件中 99% を拾える。

### プレースホルダーの除外を、典拠 ID による統合より前に置いた

`Unknown` / `Anonyme` を名前で除外するだけでは足りない。ULAN 500397994 と Wikidata
Q4233718 は典拠側の「作者不明」で、典拠 ID で束ねると 19 万件超が 1 クラスタになる。
「典拠 ID で GROUP BY すれば安全」と考えると素通りする。

### 典拠 ID が違う 2 クラスタは、名前と年が合っても統合しなかった

調べた 16 組はほぼ全部同一人物だった (Vasari が ULAN を 2 つ持つ、RKD と ULAN で
別系統になっている等)。それでも統合しないのは、典拠側の重複をこちらで判断して
よいかという別の問題になるため。緩めれば約 1,000 作品ぶん拾える。

### 名前だけを根拠にする段階では、巨大な同名グループを諦めた

同名が 200 人を超えるグループは、名前の一致に意味が無い (総当たりが O(n²) になる
問題もある)。

### 精度の推定値を行に書かなかった

各段階で測った精度 (57.3% など) はルール単位の集計値で、その行が正しい確率ではない。
行には「どのルールが発火したか」だけを書く。基準を測り直しても DB を書き換えずに済み、
LLM 由来の行も `match_method` でまとめて除外できる。生没年ゲートの結果を列に
しなかったのも同じ理由で、それは confidence を決める入力であって結果ではない。

### `person_key` を連番にしなかった

LLM の判定 (`author_merges.csv`) は `person_key` を参照しており、作り直せない。連番だと
`artists` を作り直すたびに参照が切れる。中身から決定的に導けば、同じルールで再実行する
限り同じキーになる。典拠 ID を持つクラスタは、先にクラスタを作ってから代表を選ぶ。
一致した ID をそのまま使うと、Met 側が ULAN、Rijksmuseum 側が Wikidata で一致した
同一人物が 2 つのキーに割れる。

### 自由記述からパースした生没年を `image_artists.birth_year` に書かなかった

その列は `loader.rb` が書く生の列で、上書きしても次の loader 実行で消える。
「館が構造化して持つ場合のみ」という列の意味とも食い違う。

### 採らなかった統合手法

いずれも生没年で検証した一致率が低く、拾う数と同程度の別人を混ぜ込む。

| 手法 | 一致率 | 採らなかった理由 |
|---|---|---|
| first+last (ミドルネームを落とす) | 57.3% | `William Henry Romaine Walker` と `William Walker` のような別人が潰れる |
| 編集距離 1〜2 | 29.3% | 短い名前では 3.3% でほぼノイズ。ローマ字化された中国・日本名は 1〜2 文字違いの別人が大量にいる |
| 姓 + 名イニシャル | — | 目視でほぼ全滅 (`Raudnitz & Cie` → `Rigo frères & Cie`) |
| 埋め込みによるクラスタリング | — | 翻字の違いに強くなく、同姓同名の誤統合が本質的に残る |

代わりに、段階 1〜6 で統合できなかった作者だけを LLM に判定させている (段階 7)。
LLM は非決定的なので段階 1〜6 には入れず、判定は CSV に残して DB には毎回重ね直す。
こうすれば機械ルールの再実行安全性は崩れない。`Titian` / `Tiziano Vecellio` のような
別名は文字列マッチでは原理的に届かないので、そこは LLM に任せる。作品点数の多い順に
回すのは、点数が極端に偏っていて (上位は数千点、大半は 1 点) 少ない判定回数で効くため。

## タイトルの日本語訳

### 全件を訳した。著名作品だけに絞らなかった

「著名作家の分だけ」「原題に日本語が埋め込まれている分だけ」も検討したが、対象が
狭すぎる。全件レビューは不可能なので、訳は**原題を必ず併記する前提の参考情報**と
割り切り、確度を `confidence` に出す。原題が並んでいれば、低信頼の訳も害が小さい。

### `confidence` は LLM の自己申告だけにした

図像学の定番用語辞書や著名作家リストとの突き合わせで補正する案もあったが、作っていない。
原題併記を前提にした以上、キャリブレーションの甘さが実害になりにくい。

### JOIN キーを館の作品 ID ではなく `source_url` にした

Paris Musées は 1 作品に画像が複数あると画像ごとに別レコードを作るため、作品 ID が
`images` の行と 1:1 にならない。`source_url` は画像ごとに一意で、全ソース共通。

### 訳出時の原題を CSV に残した

クローラーを再実行して原題が直ったとき、どの訳が古くなったかを機械的に見つけるため
(`apply_translations.rb stale`)。

### 原題の無いレコードは対象から外した

Wikimedia は全言語でラベルを欠く作品が約 6% ある。残しておくと `next` が毎回それを
先頭から返し、訳せない行が溜まって先に進まなくなる。

## 作者名の日本語訳

### 館が持つ原語表記を、LLM 訳より優先した

Cleveland の `name_in_original_language` (漢字名) は LLM 訳より確実なので、後から
流し込む LLM 訳で上書きしない。そのため `seed` を `artists` より先に回す。
キリル文字なども入りうるので、日本語として使えるのは CJK を含むものだけ。

訳を名寄せ結果ではなく作者エントリに付けた理由は `spec_schema.md` §3。
